## 3. 事故与教训

1. **GC 被 `SetGCPercent(-1)` 关掉**：日志里的"读取"实际禁用了 GC，6300 KiB 基线作废，落 G-21。
2. **测量干扰**：假 `kored` 进程（`prctl` 改名）+ `bin/` 被并发删除，B/C/D 档改用冻结副本重测。
3. **预算三次调整**：8/12/24 → 分层 → 16/24/48 + 目标 8/12/24，ADR-0016 冻结，不再为几百 KiB 返工。
4. **schema 未定稿就并行派发**：`triggers` 在对象数组 / 裸字符串 / 前缀字符串之间三次反复，接口应先定形再派活。
5. **`Kore-Project` 从未验证归属**：全仓按"理想组织名"写满（ADR-0017 记 77 文件 / 163 处；另有一份 134 处口径，统计范围未对齐），探测后才发现无权，全量改名 + ADR-0017。
6. **门禁规则改了实现没跟上**：48 MiB 预算文案与 `NewTimer` 定时器白名单两次出现"门禁按新口径、代码按旧口径"。
7. **注释扫描误伤三次**：`site:read` → `cron` → `site.restart`，最终裁决"剥离注释、只扫可执行代码"。

## 5. 遗留

1. **capability 方法级细粒度校验**（M1-08）：当前只校验"有没有声明"，未校验"这个方法是否需要该能力"。
2. **audit 写入**：store 无 audit 专用接口，reaper 事件与审计留 M1-09。
3. **bus 多路复用 pending map**：M1-09 收口。
4. **退避重启 / 心跳 / 热升级 / `run.json` 孤儿核对**：M1-12 / M1-13。
5. **插件仓独立 `go get`**：需先 push 并打 `pkg/pluginapi/v0.1.0` tag；当前只验证本地 `replace`。
6. **组织迁移**：未来迁入组织必须新开 ADR，同步 20+ 插件仓与各仓 `LICENSE`。
7. **`case-check` 旧仓库名告警**：规则 3 命中 ADR-0017 与台账对 `Kore-Project` 的必要引用（描述被否决项必须点名）；待 owner 决定加豁免标注还是接受长期 WARN。
