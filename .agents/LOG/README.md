# .agents · LOG（判断台账）

> 状态: draft · 归属: scribe · 更新: 2026-11-22 · 里程碑: M1

台账存的不是聊天记录，是**可追溯的判断**：谁提的、当时有哪些选项、怎么裁的、依据是什么、影响哪些文件、证据在哪。

## 1. 为什么需要它

agent 不共享记忆。会话一换、上下文一压缩，上一轮"为什么这么定"就没了——只剩一个没人解释的现状，后来者要么照抄，要么重新吵一遍。ADR 只覆盖"不可逆的架构选择"，而大量中间裁决（预算口径、验收判据、派发边界、失败归因）没有落点。

台账补的就是这一层：**让"为什么这么定"能被下一个 agent 直接读到，被质疑时有据可查，被推翻时知道推翻的是什么。**

## 2. 记什么 / 不记什么

| 记 | 不记 |
| --- | --- |
| 裁决：有多选一、有取舍、有被否决的选项 | 过程性闲聊、情绪、谁先开口 |
| 派发：谁做什么、写域、依赖、交付、commit | 工具原始输出（放 [verify/](../verify/)） |
| 失败与返工：谁判 REVISE、为什么、怎么改的 | 可再生成的中间产物（草稿、临时清单） |
| 用户指令：**引用原文**，不改写 | "用户希望…"式的二次概括 |

## 3. 四条纪律

1. **裁决当天登记**；事后补记必须在「时间」列标「补记」。
2. **派发即登记 task id**；回报后在同一条补 commit 与证据位置，不另开一行。
3. **里程碑收口时检查台账完整**：缺条目视为该里程碑未收口（G-23）。
4. **已内化模式（默认义务，不再单独标 `[PUA生效]`）**：每次派子 agent，prompt 默认极简——只写任务 + 写域 + 验收命令，规则文档让 agent 按需自读；不要把门禁全文 / PUA 契约 / 全部用例塞进 prompt。连续崩溃时先派极简 probe 验机制，正常则瘦身 prompt 重派，先看 prompt 复杂度再怀疑 agent（2026-11-22 M2 开工；裁决见 [DECISIONS.md](DECISIONS.md) 第 32 条）。

## 4. 与其它文档的边界

| 文件 | 存什么 | 回答的问题 |
| --- | --- | --- |
| [BOARD.md](../BOARD.md) | 任务状态机 | **现在**是什么状态 |
| [JOURNAL.md](../JOURNAL.md) | 事故与复盘 | 发生了什么、**教训**是什么 |
| [docs/DECISIONS/](../../docs/DECISIONS/) | 不可逆架构选择 | 架构**为什么**长这样 |
| 本目录 | 判断留痕 | **当时**怎么想的、为什么不选另一个 |

三者不互相替代：BOARD 的 `completed` 不等于判断被记录；JOURNAL 的教训不替代选项对比；ADR 不覆盖日常派发与验收口径。

## 5. 格式

### 5.1 裁决（[DECISIONS.md](DECISIONS.md)）

```text
| 时间 | 议题 | 提出者 | 选项 | 裁决 | 依据 | 影响文件 | 证据 |
```

示例：

```text
| 2026-11-22 | 预算红线是否卡死 8 MiB | 用户 → lead | ①卡死 8 MiB ②不设上限 ③红线 16 MiB + 目标 8 MiB | ③ | ①已证伪：返工成本 > 收益 ②违背资源锚点 | ADR-0016 / AGENTS G-03 | docs/DECISIONS/0016-resource-budget-final.md |
```

要求：**「选项」列必须写出被否决的方案与不选它的理由**；只写结论的条目视为不合格。

### 5.2 派发（[DISPATCH.md](DISPATCH.md)）

```text
| 时间 | task | owner | 写域 | 依赖 | 交付 | commit | 状态 |
```

示例：

```text
| 2026-11-21 | kore-impl-pluginapi | kore-impl-pluginapi | pkg/pluginapi/ | — | 9 文件 687 行 | c31d13f | completed |
```

## 6. 会话摘要（sessions/）

每个里程碑一份 `<日期>-<里程碑>.md`：用户指令原文 → lead 的理解与判断 → 本轮裁决 → 派发与交付 → 事故 → 遗留。它是**索引**，不是正文：细节一律指向 `DECISIONS.md` / `DISPATCH.md` / `JOURNAL.md`。

## 7. 收口检查

里程碑收口前逐项核对：裁决都有条目且写得出被否决项；派发都有 owner 与交付；事故都有归因；`sessions/` 有对应摘要。任一项缺失，该里程碑不得收口。
