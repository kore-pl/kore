## 4. 真装 `cron 0.7.0`（download=true）

### 4.1 安装请求与响应

```text
POST /api/v1/store/install  (X-Kore-CSRF 双提交，download=true) -> 200，耗时 3.59s
{"id":"cron-0.7.0","plugin_id":"cron","version":"0.7.0","state":"succeeded","message":"安装完成","reload":"reloaded"}
```

链路含义：`download_url` 取自**已验签索引**（`readTrusted`，`allow_unsigned=false`，验签失败即拒）→ 下载 → 按索引 `sha256` 流式校验 → 解包到 staging → 原子落位 → 写 plugins/plugin_state → 主壳重载登记。安装后落盘：

```text
/tmp/kore-store-e2e/state/plugins/cron/0.7.0/info.json
/tmp/kore-store-e2e/state/plugins/cron/0.7.0/SHA256SUMS
/tmp/kore-store-e2e/state/plugins/cron/0.7.0/bin/cron
```

产物与索引摘要独立复核（重新下载真实发布包后 `sha256sum`）：

```text
actual=23a58e0b82a4d002b20d0af33ef81f0937549c361254d0080e7af5de7c3af1e5
index =23a58e0b82a4d002b20d0af33ef81f0937549c361254d0080e7af5de7c3af1e5
SHA_MATCH=yes
```

### 4.3 `post_upgrade` 被内核识别

安装后清单（`state/plugins/cron/0.7.0/info.json` 第 54 行）：

```json
"post_upgrade": "cron.migrate"
```

用内核自身的解析入口 `registry.Load`（`internal/core/registry/manifest.go:206`，与安装/重载同一解析与校验路径）读取该目录：

```text
id=cron version=0.7.0 depth_level=production post_upgrade="cron.migrate" lifecycle=lazy
```

= 内核解析出该字段且通过 `validatePostUpgrade`（`<id>.<action>` 形态：前缀 `cron.`、动作 `migrate` 合法），**识别成立**。

关于 `post_upgrade_pending`：首次安装 `previous==""`，按 `internal/core/installer/record.go` 的 `postUpgradePending` 设计**不写** pending（避免启用即误跑迁移）；只有「旧版本→新版本」的升级才写。本轮从空状态首装，故未出现 pending 是预期行为，不构成缺陷；索引每个 id 仅有目标版本一条，无法在本索引上构造旧→新升级。

## 5. 偏差与风险（不掩饰）

### 5.1 `depth_level` 期望与真源不一致（唯一不符项）

- 任务书期望：9 个全部 `basic`（表述为「今晚收敛的结果」）。
- 实测：`cron 0.7.0 = production`，其余 8 个 `basic`。
- 事实链：`kore-plugins/index/plugins.json` 中 cron 条目即 `"depth_level": "production"`；`GET /api/v1/store/plugins` 直接返回索引条目（`internal/core/httpapi/handlers_store.go` `handleStorePlugins` → `svc.Load()` → `index.Plugins`），无二次改写。故 API/UI 必然显示 `production`。
- 判断：要么「全部 basic」的期望未覆盖 cron（production 是其真实定位），要么收敛未落盘到索引。**属需裁决事项，本轮按约束未改索引、未改代码。**

### 5.2 其它

- 安装走 GitHub 公网（`download_url`），本机直连可达（HTTP 200）；离线环境需改用 `package_path`（同一 sha256 校验链）。
- 隔离配置 `cookie_secure: "false"` 仅为本地 http 验证，不代表生产配置。

## 8. 复现要点

1. 隔离目录 + 独立 `--config`，端口 `bind(:0)` 取空闲值；`paths.*` 全落 `/tmp`，`index_dir` 指真源。
2. 口令用 `--set --stdin` 注入（不落终端、不进 argv），登录用 `curl -d @-` 从 stdin 传 JSON。
3. 写请求需 `X-Kore-CSRF` == `kore_csrf` cookie（登录豁免）。
4. 安装断言三件：响应 `state=succeeded` + `GET /api/v1/plugins` 版本 + 独立 `sha256sum` 复核。
5. `post_upgrade` 识别用内核 `registry.Load` 读安装目录，比只看文件更贴近内核行为。
