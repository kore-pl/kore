# M4-D 包级 ed25519 签名 · 纳入 M4 判定报告

> 只读研判，未改任何代码 / 测试 / 文档 / 提案。基线：提案 0004 的 M4-D 与 R4、0005 复验 S-04、索引签名脚本与公钥常量、installer 校验链。证据均于 2026-11-22 实读或实跑。

## 结论

**延 M5，不纳入 M4。** M4-B site 已出包属实，但「出包」不等于「需要包签名才能安全分发」：其在线分发链已被**索引 ed25519 + 索引声明 sha256 + installer 自算比对**三段完整覆盖，攻击者投毒须同时改索引（被 ed25519 挡）与换包（sha256 对不上），包级签名无增量安全收益。判定要点 4 结论：索引 sha256 已够。

## 三条理由

1. **在线分发链已闭环，包签名零增量（对应要点 1/2/4）**：索引签名保证 sha256 声明不可篡改，installer 又自算比对且落库 `package_sha256`（SECURITY.md:221「索引不是信任源」）。在线链路的机密性/完整性已成立；包签名保护的唯一未覆盖面是离线导入 / file:// 镜像包，而 M4-B 的验收（`site-vhost-e2e.sh`）只走在线链路，无离线分发场景。
2. **复用同一公钥使纵深防御收益归零（对应要点 3 / S-04）**：R4 钉死「复用索引公钥、不引入第二套密钥」。一把私钥同时签索引与包，一旦泄露即全链崩（S-04 点名的死法），并没有换来密钥分离；包签名在此配置下只剩「离线包来源认证」一条真实增量，不足以驱动 M4 提前。
3. **成本风险不对称**：接入需在 `Install` 增验签步骤 + `TestPackageSignature` + `TestIndexVerifyCrossCheck` + 双验窗口轮换机制。在 M4 收口窗口改动验签主链，风险是合法包全链拒装（S-04），大于当前零增量收益；提案 §5 已为 M5 预留落点，边界清晰。

## 被否选项

| 选项 | 否决依据 |
| --- | --- |
| 纳入 M4 | M4-B 出包走在线链已安全，不满足提案「出包**且需要**」的提前条件；`出包`≠`需要`。 |
| 纳入 M4 且改用独立包公钥 | 违反 R4「复用同一公钥」的硬约束，引入第二套密钥管理 + 轮换双验窗口，属 M4 范围外扩张。 |
| 删掉 M4-D 不留证据 | 违反提案 §4.4「两条路径二选一不留空」与 G-07 证据验收 / G-23 判断留痕。 |

## 复审触发条件（延期后）

1. M4-B 或 M5 出现离线导入（`--offline-dir`）/ `file://` 镜像 / 手动分发包的验收需求，包签名成为唯一来源认证时；
2. 索引私钥轮换或疑似泄露，需要独立包级信任根做纵深防御时；
3. M5 铺开 19 插件仓（提案 §5），多主体分发需要来源认证时；
4. 真实供应链事件或安全审计要求把 M4 签名强制化时。

## 关于「不出包证据」的口径

M4-B 出包属实，无法伪造「不出包证据」。按判定要点 4，附的是**出包链路已由索引签名 + sha256 覆盖、无需包签名**的证据（见上表五行），如实支撑「延 M5」结论，不篡改事实凑模板。
