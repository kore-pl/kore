# i18n 结构性发现：骨架完整，页面内部文案未接 tr()

> 归属: r8-i18nui (task-11) · 日期: 2026-11-24 · 裁决: lead 选 (b) 发现型交付
> 结论: 任务卡前提「i18n 骨架缺项、en-US 需补页面文案」与代码事实不符。真问题是「两表已完整镜像，但页面视图未接 tr()」。本卡不硬造键、不扩写域、不破 G-11。

## 1. 写域路径笔误

任务卡写的 `web/i18n-en-US.js` 在源码树不存在——那是构建产物名（`web/dist/i18n-en-US.js`，被 `.gitignore` 忽略）。真实源码是 `web/i18n/en-US.js`，`wc -c` = 3174 字节，与任务卡描述的数字吻合。

依据：ADR-0021 §文件组织（源码按 `web/i18n/<locale>.js`，产物拍平为 `web/dist/i18n-<locale>.js`）+ `Makefile:96-97`（`cp web/i18n/en-US.js web/dist/i18n-en-US.js`）。

## 2. 两表 68=68，双向差集空——无合法可补项

```
zh-CN key 数: 68
en-US key 数: 68
comm -23（zh 有 en 缺）: 空
comm -13（en 有 zh 缺）: 空
```

`diff -y` 逐行比对 68 个 key 顺序与拼写完全一致。要求「key 与 zh-CN 逐条对应，不臆造新 key」在当前代码事实下**没有补的对象**：现有英文表已是中文表的完整镜像。任何 `sites.*` / `backup.*` / `ssl.*` 页面文案键在两表都不存在，加进 en-US 只会制造 zh-CN 侧无对应的孤儿键。

## 3. 五个高频视图 tr() 调用数 = 0

| 视图文件 | 中文串出现次数 | tr() 调用数 |
| --- | --- | --- |
| `web/sites.js` | 447 | 0 |
| `web/files.js` | 513 | 0 |
| `web/db.js` | 589 | 0 |
| `web/ssl.js` | 335 | 0 |
| `web/backups.js` | 357 | 0 |

整仓视图的 i18n 调用点只在 `shell.js`(14) / `settings.js`(10) / `store.js`(1)。页面内部文案全是硬编码中文——**加 key 不会让页面显示英文，因为无人调用**。更糟的是 `web/i18n.js:42` 的回退链：当前语言表 → zh-CN 表 → key 名。若往 en-US 加 zh-CN 没有的键，英文态下查不到中文回退，会直接把 `sites.xxx` 这样的键名显示给用户，比现状的半中半英更差。据此判定：加页面文案 key 是**有害改动**，禁止。

## 4. 预算真相：en-US 不进 i18n 增量门禁

`scripts/frontend-check.sh:54-66` 卡的是 `i18n.js + i18n-zh-CN.js` 两文件的 gzip 合计 ≤ 3072 字节（ADR-0021 §关键决策 6：en-US 只在切英文时注入，不进首屏）。实测：

```
i18n.js        gzip -9: 1594 字节
i18n-zh-CN.js  gzip -9: 1328 字节
i18n 增量合计:       2922 字节 / 预算 3072 字节（余量 150）
首屏合计:           72729 字节 / 预算 307200 字节（余量 234471）
```

改 `web/i18n/en-US.js` **不影响这两个数字**。任务卡把「i18n 增量 gzip ≤3072」当成 en-US 的约束，是对门禁的误读；en-US 自身当前 gzip -9 = 1338 字节。

## 5. settings.upgrade 三处缺键——不会露键名

`web/settings.js:233/263/265` 有 `tr('settings.upgrade.title' / 'start' / 'rollback', '中文 fallback')` 调用，但这两张表都无对应 key。这不构成缺陷：`settings.js:108-115` 的本地 `tr()` 与 `shell.js:122` 的同名函数在 i18n 查不到时回退到调用点传入的硬编码中文 fallback（并检查 `hit !== key`，避免键名外露）。英文态这几处显示中文，属已知的阶段性混合态，不是 UI 事故。

## 6. 结论与后续

- **这不构成 G-11 违规**，是 ADR-0021 §关键决策/后果明确承认的阶段性取舍（「导航英文、页面中文」的混合态），原文写明「不当作缺陷修」。
- r8-simplicity 的原始扫描结论「i18n 骨架缺项」应予修正为「骨架完整（68=68 镜像），页面未接 tr()」——这个区分直接影响排期优先级。
- **页面内部文案迁移需另立卡**，且必须**同时**改三处：zh-CN 表加键 + en-US 表加键 + 视图接 `tr()` 调用。三者缺一就会出现孤儿键或键名外露。**不在本卡范围**（本卡写域原仅 en-US 源码，G-11 明确不做全量框架）。
- 并行轨道协同：已同步 r8-progressui——备份/部署进度文案目前不走 tr()，若后续接入需先在 zh-CN 建键再通知 en-US 补齐。
