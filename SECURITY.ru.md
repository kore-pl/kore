# Раскрытие уязвимостей безопасности

Этот файл описывает порядок раскрытия, а не проект безопасности. Проект ядра — в docs/SECURITY.md, модель угроз Kore — в репозитории kore.

## Область действия

Covered: the kore kernel and main shell (`cmd/`, `internal/`, `pkg/pluginapi`), officially maintained plugin repositories (`kore-plugin-<id>`), and the official plugin index and presets (`kore-plugins`).

## Поддерживаемые версии

| Версия | Статус | Примечание |
| --- | --- | --- |
| `0.1.x` | Да — принимается и исправляется | Текущая MVP-ветка; исправления только для последнего патча. |
| `< 0.1` | Нет — не поддерживается | Предпросмотр/разработка; обновитесь. |

На стадии 0.x поддерживается минимальный набор: исправляется только последний патч каждой минорной ветки; старые патчи не портируются.

## Поверхность атаки в этом репозитории

Удалённые действия и запись на хост ограничены объявленными возможностями; обход считается уязвимостью. Сокеты плагинов создаются оболочкой с ограниченными правами; обход прав сокета или чтение чужих данных плагина — уязвимость.

## Сообщение

Предпочтительно: GitHub Security Advisory в этом репозитории («Сообщить об уязвимости», приватно, без публичного issue). Резервная почта: pengtang1024@users.noreply.github.com с темой `[kore security] <repo>`. Не создавайте публичные issue и не публикуйте эксплойт-детали в обсуждениях или PR.

Укажите: затронутую версию или коммит, шаги воспроизведения или PoC, оценку влияния, известность problem и предпочтение по атрибуции.

## Сроки и раскрытие

Подтверждение в течение 72 часов с предварительной оценкой; сложные случаи получают план расследования. Согласованное раскрытие со стандартным окном 90 дней; свяжитесь сначала, если нужно досрочное раскрытие (например, активная эксплуатация). Зафиксируйте исправления в CHANGELOG.md без деталей эксплойта и при необходимости опубликуйте предупреждение.
