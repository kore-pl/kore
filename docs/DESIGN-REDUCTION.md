## 1. 设计北极星（沿用已有锚点，不另起价值观）

**一句话：Kore 的界面应是「3 秒看到健康、1 次点击到主任务」的薄壳控制台——信息按层级落下，而不是平铺堆满。**

北极星不新增价值观，只是把项目既有锚点收束成一句可判据的话：

- **能力对标、形态不对标**：宝塔把 40+ 功能塞一个进程；Kore 保持薄壳，能力在插件仓（`docs/FEATURE-PARITY.md:16`）。
- **体验锚点：克制视觉、表格优先**——「首次使用会觉得信息少，熟练后操作路径更短」（`docs/FEATURE-PARITY.md:61`）。
- **不把「功能多」当「对标成功」**（`docs/FEATURE-PARITY.md:157-159`）：功能数量对齐但机器从 1 GB 吃到 4 GB 是失败；常驻 ≤3 / ≤24 MiB，20 个插件只有 3 个允许常驻。界面同理：入口数量对齐不等于 usability。
- **问题不是丑，是没有层级**（`docs/DESIGN-AUDIT.md:118`）：12px 占 71%、24px 间距几乎不用、17/18 页内容区无图标、空态只有一句话 → 眼睛无处落下。
- **项目反样板红线**：同屏内容区最多 2 个容器级区块（`docs/FRONTEND.md:228`）、KPI 磁贴 ≤4 且每个可下钻（`docs/FRONTEND.md:240`）、禁用「...」菜单藏关键操作（`docs/FRONTEND.md:237`）、触摸目标 ≥44px（`docs/FRONTEND.md:67`）。

**判定口径（供后续每项验收）**：新增一个可见控件，必须同时说明它替换了哪个旧控件，或证明它属于「选中后才出现」的上下文态；只加不减的改动不予合入。

## 2. 五个堆砌点的逐一减法方案

> 总原则：**减法 ≠ 删功能**。每个被移走的入口只有两种归宿——① 合并进同类 hub 的既有 tab / 折叠区；② 下沉为选择态、抽屉、详情或已有 hub 的第二层。不得为此新建 hub（G-11）。
