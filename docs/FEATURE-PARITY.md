## 1. 对标原则

1. **能力对标、形态不对标**：宝塔把 40+ 功能塞进一个进程；kore 保持薄壳，能力全在插件仓库里。
2. **每行必须有归属**：要么给插件 id，要么写"不做 + 理由"。矩阵里不允许空单元格，也不允许"规划中"这种模糊状态——只有 M2/M3/M4/不做。
3. **不追专业版的商业件**：面板的"专业版"卖点里有一部分是**托管服务**（云端备份空间、远程扫描、多机管理），kore 只做本地能自证的部分。
4. **多用户明确不做**：单管理员 + 审计（`audit` bucket）。多用户/多租户是非目标，不是"以后再说"。
5. **深度分级必须外显**：插件分 **生产级（12）** 与 **基础级（8）**；基础级只保证核心路径，边界用例与高级配置延到 v1.1。商店与对标矩阵都必须显示等级标签，不能拿基础级冒充生产级。

## 3. 差异说明汇总

| 差异 | 原因 | 用户可见后果 |
| --- | --- | --- |
| 不做多用户/子账号 | 单管理员是鉴权与数据模型的前提（`/etc/kore/config.yaml` 单口令 + `audit`） | 团队协作只能共享一个管理员账号；操作可追溯但不可分权 |
| 不做云端扫描/规则订阅 | 红线④：无联网校验、无隐藏上报 | WAF/木马检测的规则是本地版本，需用户自己更新 |
| 不内置数据库/运行时二进制 | 单二进制 ≤ 25 MiB + 依赖白名单 3 个 | 装 kore 前需宿主已有 MySQL/PHP；插件负责探测与给安装命令 |
| 监控只做本机 | 不做集群与分布式（非目标） | 多机需每台各装一个，无聚合视图 |
| 备份不代管存储 | 无账号、不托管用户数据 | 本地备份已交付；异地/S3 按 G-11 不做，由外部同步工具搬运（backup 插件 README:6） |
| 信息密度不同 | 体验锚点：克制视觉、表格优先 | 首次使用会觉得"信息少"，熟练后操作路径更短 |

## 4. 覆盖统计

**22 项能力域**由 20 个插件承载（`site` 一个插件覆盖站点/域名/反代三项，故域数 > 插件数），另有 6 项明确不做：

| 分类 | 域数 | 插件数 | 能力域 |
| --- | --- | --- | --- |
| 生产级 | 14 | 12 | 站点、域名、反代、SSL、PHP、MySQL、Redis、文件、cron、监控、防火墙、备份、日志、一键部署 |
| 基础级 | 8 | 8 | Node、Python、PostgreSQL、WAF、SSH 加固、完整性、DNS、容器 |
| 合计覆盖 | **22** | **20** | — |
| 明确不做 | 6 | — | 多用户 RBAC、集群/多机、模板市场、厂商云存储深度集成、拖拽建站、i18n 全量框架 |

数据能力口径（round 16 收口，不新增"不做"域）：**MySQL `db-mysql.exec` 受控写已交付**（两级确认 + 写白名单 + `system:admin` + 自动审计，commit `01a6729`+`0255f55`，G-28 双端证据 `.agents/verify/db-mysql-exec-ui.md`）；**PG exec 对称进行中**（task-176）；**可视化行编辑已裁决暂不做**（范围取舍，可重开判据见 [FEATURE-GAP-BACKLOG.md](./FEATURE-GAP-BACKLOG.md) C7，未列入上表 6 项明确不做）。本口径不改变 22 域 / 14 生产级 + 8 基础级 / 6 不做的计数。

| # | 不做项 | 理由 |
| --- | --- | --- |
| 1 | 多用户 RBAC | 破单实例鉴权模型；要做先改数据分区与权限矩阵，等于重做产品 |
| 2 | 集群 / 多机 | 明确非目标；每台各装一个，无聚合视图 |
| 3 | 模板市场 | 需要审核与分发体系；插件索引已够，模板走 `app-deploy` 模板文件 |
| 4 | 厂商云存储深度集成 | 厂商 SDK 破依赖白名单且引入账号体系；S3/对象存储按 G-11 明确不做，异地走外部同步工具 |
| 5 | 拖拽建站 | 与"克制视觉 + 插件化"冲突，是另一个产品形态 |
| 6 | 多语言全量框架（i18n） | MVP 仅中文；「中文为主 + 英文可选」骨架已按 ADR-0021 落地，扩语言或引框架仍不做 |

## 7. 对标验收判据

"有"不是看界面有没有按钮，是看能不能跑出结果。每个能力域给出可执行判据：

| 能力域 | 验收方式（可执行） | 判定 |
| --- | --- | --- |
| 站点 | 建静态站点 → `curl` 200 → 删除后端口释放 | 三步全过 |
| 域名/伪静态 | 绑定域名 + 规则命中 301 | `curl -I` 断言 Location |
| 反向代理 | upstream 指向本地 8080 → 透传 `X-Forwarded-For` | 响应头存在且值正确 |
| SSL | 签发 → 证书链校验 → `cert.renew_due` 事件后自动续期 | 证书链 OK + 事件消费成功 |
| PHP | 部署 `index.php` → 页面输出版本号 | 200 + 版本匹配 |
| Node | 示例服务起 → 端口可访问 → `kill` 后自动重启 | 200 + 重启记录 +1 |
| Python | venv 模板 → gunicorn 起 → 访问 | 200 |
| MySQL/MariaDB | 建库、建用户、慢查询视图、备份钩子 | 四项全成功 |
| PostgreSQL | 建库、连接、`pg_dump` 钩子 | 三项全成功 |
| Redis | 键扫描上限 1 万 + 内存策略读取 | 上限生效、无全量遍历 |
| 文件 | 编辑保存、上传 10 MiB、解压、改 644 | 四项全成功 |
| cron | 每分钟任务 → 执行记录 2 条 + 输出落 `tasks/` | 记录数与输出文件匹配 |
| 监控 | 阈值触发 → webhook 收到 1 次 | 回调 payload 含指标值 |
| 防火墙 | 放行端口 → `ss -ltn` 可见；规则仅 `kore:` 段 | 断言两条 |
| WAF | 提交注入 payload → 403 + 拦截日志 | 403 + 日志命中 |
| SSH 加固 | 5 次失败登录 → 封禁 → 解封 | 规则存在/消失 |
| 完整性 | 改动基线文件副本 → 事件 + 告警 | 事件含文件路径与哈希 |
| 备份 | 本地备份一次 → 恢复并校验 sha256（S3 按 G-11 不做，不纳入判据） | 恢复成功且哈希一致；下载链路 G-28 时 0 份包未实机验证属证据缺口 |
| 日志 | 关键字过滤 + 下载 | 行数与内容匹配 |
| 一键部署 | WordPress 模板 → 前台可访问 → 回滚 | 成功 + 回滚后无残留 |
| DNS | 新增 A 记录 → `dig` 命中 | 解析结果正确 |
| 容器 | 列容器、起停各一次 | 状态变化可查 |
| 商店 | `store/refresh` → 装 → 升级 → 卸载 | 四步状态正确 |
| 场景预设 | `kored install --scenario web-pro --yes` | 插件齐备、常驻 ≤3 个、常驻合计 ≤19.2 MiB（红线 24） |

## 8. "专业版商业件"边界

宝塔/1Panel 专业版里有一部分卖点本质是**托管服务**，kore 明确不追：

| 商业件 | 依赖什么 | kore 的处理 |
| --- | --- | --- |
| 云端备份空间 | 厂商账号 + 存储计费 | 本地备份已交付；异地按 G-11 不做，由外部同步工具搬运 |
| 远程木马扫描/云查杀 | 联网特征库 | 只做本地文件完整性基线（`integrity`） |
| 多机管理/集群视图 | 中心端 + agent | 每台各装一个，无聚合视图（非目标） |
| 短信/电话告警 | 第三方通道凭据 | 只做 webhook/邮件/IM 机器人，短信与电话由用户自接（R37 全文：BT 短信需官网开通商业服务、公众号自承折叠延迟，1Panel 短信/Bark 等渠道；我方缺短信/Bark/公众号属形态差异/有意不做，不判落后） |
| 规则订阅/WAF 云规则 | 联网更新通道 | 本地规则集 + 可 diff 的规则文件 |

## 10. 对标口径的三个坑

| 坑 | 表现 | 本项目的处理 |
| --- | --- | --- |
| 把"装了"当"有" | 商店里挂着插件，但依赖没装、权限没给，点开就报错 | 每能力域有可执行验收（§6），装完必须跑通才算覆盖 |
| 把"专业版有"当"必须做" | 照抄商业件，背上账号、云服务、审核 | §7 明确五类商业件不追，写清替代路径 |
| 把"功能多"当"对标成功" | 功能数量对齐，但机器从 1 GB 吃到 4 GB | 常驻硬门禁 ≤3 个 / ≤24 MiB；能力再全也不许常驻堆叠 |
| 把"插件"当"免费扩展" | 每加一个能力就多一个常驻进程，最后回到"大而全" | 20 个插件里只有 3 个允许常驻；其余 lazy/oneshot |
| 把"面板"当"主机" | 面板自身占用比业务还高 | 主壳 ≤8 MiB、空闲 CPU ≤0.1%、空载出站 0 |
