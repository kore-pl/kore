## 1. 九类目标

### 1.1 功能

| 目标 | 量化判据 | 验收命令或方式 | 责任里程碑 |
| --- | --- | --- | --- |
| 能力覆盖对标专业版 | **20 个产品插件（12 生产级 + 8 基础级）+ 1 验证件 `echo`**；**8 个场景预设**；商店可装/升/卸；**覆盖 22 项能力域、6 项明确不做** | 21 个仓库可经商店安装与卸载；`FEATURE-PARITY` 每行有状态（做/延后/不做）且无空单元格 | M2 起 / M4 收口 |
| 插件名单（唯一来源：[PLUGIN-CATALOG.md](./PLUGIN-CATALOG.md) §6.1） | **生产级 12**：`site` `ssl` `runtime-php` `db-mysql` `file` `backup` `cron` `logs` `monitor` `firewall` `redis` `app-deploy`；**基础级 8**：`runtime-node` `runtime-python` `db-postgres` `waf` `ssh-guard` `integrity` `dns` `container`；`echo` 为验证件、**不评级** | 与 CATALOG §1–§5 表格逐字一致（12 + 8 + 1 = 21 个仓库） | M2–M4 |

> 口径澄清：索引中 echo 的 depth_level=basic 仅为 schema 两值约束下的占位，验证件不参与 12 生产级 / 8 基础级评级；12/8 统计只数 20 个产品插件。

### 1.3 资源

| 目标 | 量化判据 | 验收命令或方式 | 责任里程碑 |
| --- | --- | --- | --- |
| 管理者不变成负担 | **硬红线 / 目标**两档：主壳空载 **红线 ≤16 MiB / 目标 ≤8 MiB**；单常驻插件 **红线 ≤24 MiB / 目标 ≤12 MiB**；常驻合计 **红线 ≤48 MiB / 目标 ≤24 MiB**；同时常驻 **≤3（推荐 ≤2）**；单二进制 ≤25 MiB；首屏 ≤300 KiB gzip；空闲 CPU ≤0.1%（60 s ≤60 ms）；goroutine ≤20；fd ≤64；空载出站 0。运行时默认 `GOGC=50` + `GOMEMLIMIT=6MiB` + `GOMAXPROCS` 上限 8（仅 CPU>8 时收敛） | `make mem`、`make idle`、`make budget-check`（三件套同时绿）；**红线超即判未完成，目标未达只记趋势** | M1 主壳 / M2 常驻 / M4 全量 |
| 预算定案 | 依据 **ADR-0016**：上表红线与目标为最终值，**除安全事故或用户明确要求外不再调整**；任何再调整必须新 ADR + 全链同步 | `docs/DECISIONS/` 中对应 ADR 存在且被 V1-GOALS/VISION/RESOURCE-MODEL 引用 | M4（冻结） |

## 2. v1.0 gate 定义

**一句话**：九类目标的**全部取证项通过**（且无 P0 未关问题）才允许打 `v1.0.0`；缺一类、缺一条可复现证据，都不叫 v1。

| # | 类 | 必需证据 | 判定 |
| --- | --- | --- | --- |
| 1 | 功能 | 21 仓库商店安装/卸载记录 + `FEATURE-PARITY` 每行状态 | 无空行、无"规划中" |
| 2 | 质量 | 12 个生产级仓的 `tests/fault/` 四类用例 + CI 链接 | 12/12 绿 |
| 3 | 资源 | `make mem` / `make idle` / `make budget-check` 输出 | 全部在阈值内，60 s 中位数 |
| 4 | 性能 | 冷启动 20 次 p95 + 启动到就绪耗时 + API p95 | 300/1000/50 ms 达标（SLO 超时须记录不隐瞒） |
| 5 | 兼容 | CI 发行版矩阵 10 行 + `make compat-info` | 10/10 通过，amd64 必过、arm64 按 M2 起门禁 |
| 6 | 安全 | 审计报告 + `ss -tnp` 空 + 策略拦截用例 | 三项无例外 |
| 7 | 运维闭环 | 端到端脚本输出（五步） | 一次跑通，含失败错误可读性检查 |
| 8 | 开放 | 干净目录构建日志 + 断网安装日志 + 篡改拒绝日志 | 三项均有输出 |
| 9 | 不做 | G-11 拦截记录 | 6 项均无例外批准 |

| 类 | 首次达成 | 最终验收 |
| --- | --- | --- |
| 功能 | M2（框架 + 前 7 插件 + 商店 + 预设） | M4（20 插件 + 8 预设全量） |
| 质量 | M3（12 生产级故障注入） | M4（回归复跑） |
| 资源 | M1（主壳红线 ≤16 MiB / 目标 8 MiB）/ M2（常驻 2 个，合计红线 48 / 目标 24 MiB） | M4（全量复测 + ADR-0016 冻结核对） |

## 4. 目标不被稀释的机制

1. **新增需求必须归类**：任何需求先回答"属于九类中的哪一类"，并写明**是否改变量化判据**。归不进九类 = 不属于 v1，进 backlog。
2. **改判据必须走 ADR**：任何量化判据（数字、阈值、验收方式）的调整，必须落 `docs/DECISIONS/` 的 ADR，写清旧值、新值、理由、受影响文档清单。**禁止在 PR 里顺手改数**。
3. **数字唯一来源**：本文件的数字与现役文档逐字一致；冲突时以"最近一次 ADR + 全链同步"为准，不允许两套数字并存。
4. **里程碑不可塞入非目标**：G-11 的 6 项不做，不因"顺手"进入任何里程碑；要推翻必须 ADR 并经 architect + 蓝军双评审。
5. **验收权分离**：目标达成由 verifier 独立取证，实现者不得自我勾选；gate 判定以证据文件为准，不以口头结论为准。
