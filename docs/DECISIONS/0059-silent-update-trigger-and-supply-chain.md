# ADR-0059：静默更新触发、批量编排与更新源供应链（默认关闭的可选出站）

## 1. 背景与问题陈述

静默自更新的另外三块缺口（草案 §2.2 / §2.4）：

1. **无批量入口**：CLI `--scenario` 目前明确回 `E_UNSUPPORTED`（`cmd/kored/install.go:61-72`）；`POST /api/v1/store/install` 请求体是单 id/version；market.Service 无批量配置；商店预设「一键安装」是禁用态（草案 `self-update-design-draft.md:58`）。
2. **自动触发缺失**：scheduler 是 G-19 / ADR-0019 唯一合法周期源（`internal/core/scheduler/loop.go:8,18-24`，单 goroutine + 单 ticker），market 零 ticker；`kored upgrade --bin` 拒绝 URL（`cmd/kored/upgrade.go:10-14`），内核二进制没有「已验签索引 → https 资产 → sha256」的供应链入口（插件包已有 `InstallFromURL`，见 `internal/core/market/download.go:12-26,29-54`）。
3. **可选项需要裁决**：拉索引必然有出站连接，与 G-10「无联网 / 无遥测」存在张力；旧版本清理与回滚能力也需要磁盘预算权衡。用户已在 2026-11-26 裁决 U2=A、U4=允许但默认关闭、U6=可配置保守默认（task-41 §用户裁决）。

## 2. 选项对比（多选一，含被否决项）

### 2.1 批量入口（U2）

| 选项 | 做法 | 优点 | 代价 / 风险 | 结论 |
| --- | --- | --- | --- | --- |
| **A. 批量更新编排器（复用 reloadOne）** | 一次触发 → 读索引算待更新项 → 按依赖序逐条调现有单条 store/install → 复用 `reloadOne`（`cmd/kored/serve_runtime.go:262`）→ 汇总 + 失败分诊 | 复用已验证的单条热更新路径（零停服）；改动最小；单条失败不整批回滚（草案 §3.1、§2.2） | 依赖排序 / 幂等 / 部分失败语义要 design；`stale_versions` 需配套清理 | **采纳（主）** |
| B. 补齐 CLI `--scenario` 真批量 | 一次命令装完预设 | 对齐既有预设模型，离线可用 | CLI 路径仍需停服（bbolt 独占锁，`store.go:95-100` / `install.go:102-108`），与零停服承诺冲突；只能作离线补充 | **采纳为离线补充，不进静默主链** |
| C. 批量 API 改对外 schema（`items[]`） | 一次请求服务端统一编排事务 | 单次调用、统一事务边界 | 改对外 schema（G-24 显式类型）；失败语义复杂；与 `reloadOne` 单 id 回调交互要重设；需独立 ADR | **留完整期评估（本 ADR 不采纳）** |

### 2.2 触发与供应链（U4）

| 选项 | 做法 | 优点 | 代价 / 风险 | 结论 |
| --- | --- | --- | --- | --- |
| **A. scheduler 单 ticker 内注册内置更新检查任务** | 复用 ADR-0019 白名单（`cert_renew` 已是内置任务先例）；任务做「读已验签索引 → 比对版本 → 下载 → 校验 → 触发更新」；`IsOffline` 短路 | 不新增 ticker、合规 G-19；离线零报错；用户可配置关闭 | 与 G-10 张力，须明确为「用户可选更新源拉取」并默认关闭；新任务要登记 ADR-0019 | **采纳** |
| B. 事件驱动 / 用户手动触发 | 不做周期检查，点「检查更新」或 webhook 触发 | 完全不碰定时器 | 不满足「自动发现、零操作」承诺；webhook 引入对外入口与鉴权面 | **否决为主链**，仅作手动兜底（不新开对外入口） |
| C. 独立常驻自更新守护进程 | 另起一个进程跑检查 | 与 kored 解耦 | 违反 G-05 / 资源预算（G-03）；安装目录外写入违反 G-31 / ADR-0023 §3.5 | **否决** |

### 2.3 备份 / 磁盘（U6）

| 选项 | 做法 | 优点 | 代价 / 风险 | 结论 |
| --- | --- | --- | --- | --- |
| **A. 可配置保守默认 + 超限自动清理** | 备份保留份数、旧版本磁盘上限做成配置项，默认保守（保留 2 份，上限按 G-03 预算比例取）；`stale_versions` 超限自动清理 | 兼顾回滚能力与磁盘预算；对齐 1Panel 备份份数可配 | 自动清理需防止把「唯一可回滚版本」删掉；需白话提示 | **采纳** |
| B. 固定保留 1 份、不可配 | 永远只留 `.prev` / 上一版本目录 | 简单 | 无回滚余量、无配置面；与竞品「份数可配」差距明显 | **否决** |
| C. 永不自动清理（维持现状：`market/types.go:104-106` 只提示） | 磁盘只增不减 | 零误删风险 | 版本越多磁盘越涨，终会撞 G-03；用户要手工清理，违背零操作 | **否决** |
| D. 上限与份数写死为全局常量、无配置项 | 不引入配置键 | 改动最少 | 无法按安装规模调整，复现 1Panel 反例；用户不能调 | **否决** |

## 3. 裁决（2026-11-26）

**U2=A（B 离线补充，C 留完整期）；U4=允许可关闭的更新源拉取且默认关闭；U6=可配置保守默认 + 超限自动清理。** 被否决项见 §2 各表与 §6。

### 3.1 触发链（单 ticker / 离线短路）

1. 在 `internal/core/scheduler/` 的**唯一** ticker 上注册内置任务 `update.check`（`plugin="kore"`，内置方法；仿 `cert_renew` 的迁移先例，ADR-0019 §G-19 修订行）。不新增 ticker、不使用 `time.AfterFunc` / 周期循环（G-19）。
2. 任务默认**不启用**；启用开关与更新源地址一并作为用户配置项，且**默认关闭 / 默认空**（§3.3）。禁用时 scheduler 不启动该任务，空闲行为与今天一致。
3. `IsOffline` 为真时任务**直接短路**，返回「离线跳过」，不报错、不重试、不产生出站连接（借鉴 1Panel `SearchUpgrade` 的离线短路，草案 §2.4 / §5 第 1 条）。
4. 验签失败时带 `requires_restart:true` 提示（`internal/core/market/verify.go:27-31`），本次不更新；不把验签失败降级为「用未签名索引继续」。

### 3.2 供应链：已验签索引 → https 资产 → sha256

1. **信任根**：只消费已验签索引（`market.Verify` / ADR-0025 方案 A 长期密钥），索引里每条资产带显式 `download_url` 与 `sha256`（`internal/core/market/types.go:33`、`download.go:29-54` 已实现「从索引取 url+sha 下载」的插件路径）。
2. **来源约束**：`download_url` 必须是 https 绝对 URL（安装器已有验证，`download_test.go:125` 反例），拒绝 URL 省略 / file: 混入（离线包走显式本地路径，不伪装成索引下载）。禁止 URL 拼接猜测：缺 `download_url` 直接 `E_INVALID`（`download_test.go:109-118`）。
3. **校验先于替换**：下载流式计算 sha256 并与索引逐字比对，不一致则目标字节不动（`cmd/kored/upgrade.go:12-13` 的既有不变量）。内核二进制下载到**本地临时文件**后，再交给 `kored upgrade --bin <本地文件> --sha256 <hex>`（该命令拒 URL，`upgrade.go:10-14`），复用原子替换 + `.prev` + pending + `--no-block` 重启 + 新进程 finalize 的完整链（`:150-208,265-295,340-379`）。
4. **公钥轮换**：验签公钥是编译期常量，换钥必须 rebuild + 重启才生效（ADR-0025 §7 / `docs/RUNBOOK.md:68-74`）；本 ADR 不改验签体系，只在新二进制重启后自然承接新公钥。
5. **不碰远端**：全流程只做本地下载与本地文件替换 / unit 重启，**绝不 git push / tag / PR、不触发任何 CI**（ADR-0056 §6；GitHub 只 `workflow_dispatch`）。

### 3.3 G-10 符合性论证（关键）

G-10 原文禁的是「强制账号、强制联网校验、隐藏上报、功能封锁」，判据是 `internal/core` 禁用词零命中（见 [ADR-0054](./0054-user-configured-webhook-egress.md) §1 对判据的逐字引用）。本 ADR 的可选出站按 ADR-0054 六条判据逐条对齐，并额外加「默认关闭」一条：

| # | ADR-0054 判据 | 更新源拉取的对应事实 |
| --- | --- | --- |
| 1 | 出站目标只来自用户配置，无硬编码地址 | 索引源 URL / 资产 `download_url` 全部来自用户显式配置与已验签索引；源码无内置更新服务器地址 |
| 2 | 用户显式启用，默认无配置 | **默认关闭 + 源地址默认空**；未开启时不拉索引、不下载、出站 0（新增的更严格要求） |
| 3 | 无周期/后台自动出站（例外场景本身） | 检查任务虽挂在 scheduler，但默认禁用；开启后是用户明示的自动检查，属用户授权行为，不是隐藏轮询；离线 `IsOffline` 短路 |
| 4 | 不做任何内置遥测语义 | 只拉已验签索引与公告资产，不上传版本、设备标识、使用数据；无 session / heartbeat / analytics / phone-home |
| 5 | URL / 凭据不落明文日志 | 只记 scheme://host + 状态码 + 版本，不记完整查询串或凭据（G-30） |
| 6 | UI 明确告知边界 | 设置页白话说明「如需自动检查新版本，请填写更新源并开启；Kore 默认不联网、不收集任何数据；关闭后完全离线」 |

**结论**：G-10 禁的是强制联网 / 隐藏上报，不是「用户可选、默认关闭、只拉已验签资产」的更新源；本设计符合 G-10 精神，且比 ADR-0054 的 webhook 例外更严格（多一条默认关闭）。**任何**自动定时上报、安装后默认开启的云端连接、未披露地址、隐藏远端拉取仍按 G-10 原判据零命中处理，不在本 ADR 的例外范围内。

### 3.4 批量编排（U2=A）

1. 编排器读已验签索引 → 计算待更新项 → 按 `depends_on` 依赖序排序 → 逐条调用**现有单条** store/install 原语（在线路径自带 `reloadOne`，`serve_runtime.go:262`）→ 汇总 `{id, version, previous_version, status}` → 失败按 HTTP 码分诊并继续其余项（不整批回滚，草案 §3.1）。
2. B（`--scenario` 真批量）只作**离线 / 演练补充**，不接静默主链；CLI 路径的停服限制如实告知（草案 §2.3）。
3. C（批量 API schema `items[]`）本 ADR 不采纳：对外 schema 改动需独立 ADR 与 G-24 复核，留完整期。

### 3.5 备份与磁盘（U6=A）

1. 新增配置项：`backup.keep_count`（默认 **2**）、`backup.max_disk_bytes`（默认按 G-03 预算比例取保守值，比如 `<install>` 磁盘预算的 10%，具体常数在实现任务卡按 G-03 实测校准）。**份数与上限均可配**，对齐 1Panel「备份份数可配」。
2. `stale_versions` 超过份数或磁盘上限时自动清理最旧版本目录（`market/types.go:104-106` 现状是「不自动删除、只提示」，本 ADR 改变该语义，需同步 market / 前端文案，G-06）。**保底**：至少保留 1 个可回滚版本 + `.prev`，清理不得把唯一回滚材料删掉；清理动作写审计（actor / 路径 / 保留份数 / 删除清单）。
3. 清理前的版本目录必须已完成新版本生效确认（插件 reload 结果 / 内核 finalize 成功），否则跳过清理并告警；清理失败不回滚已成功的更新，但留 WARN 与可重试入口。
4. 自动清理只作用于 `<install>` 内的版本目录，不新增 ADR-0023 §3.5 清单外的安装目录外写入（G-31）。

## 4. 被否决选项与依据

| 选项 | 否决依据 |
| --- | --- |
| 批量 C：改 `store/install` 对外 schema 为 `items[]` | 对外契约改动需独立 ADR + G-24 复核；单条失败语义与 `reloadOne` 回调交互复杂；完整期再评估。 |
| 触发 B（webhook / 手动）作主链 | 不满足自动发现 / 零操作；新增对外入口与鉴权面，违背「零新入口」的最小改动原则。 |
| 触发 C（独立守护进程） | G-05 常驻组件 + G-03 资源预算 + G-31 安装目录外写入三重违规；kored 自身已有唯一合法周期源。 |
| 备份 B（固定 1 份不可配） | 无回滚余量、无配置面，与竞品「份数可配」差距明显。 |
| 备份 C（永不清理） | 磁盘只增不减，终撞 G-03；把清理成本转给用户，违背零操作。 |
| 备份 D（写死常量） | 用户不能按安装规模调整，缺少配置入口。 |
| 「默认开启更新源」或「静默遥测版本信息」 | 直接违反 G-10（强制联网 / 隐藏上报）与用户 U4 裁决；任何此类需求必须新开 ADR 并先解 G-10。 |

## 5. 后果

**正面**：不动 G-19 唯一周期源；复用既有验签、下载、安装、upgrade、reloadOne 原语；离线场景零报错零出站；用户可完全关闭更新源；回滚能力与磁盘占用均可控可配。

**代价 / 风险**：需登记 ADR-0019 新内置任务与 ADR-0025 的内核资产字段（草案 §6.1）；`market/types.go` 的 stale 语义改变要同步前端（G-06）；开启更新源后会出现用户明示的出站连接，验收报告必须区分「配置前出站 0」与「开启后短连接」两种基线（ADR-0054 §4 口径）；自动清理有误删窗口，靠「生效确认后才清 + 保底 1 份 + 审计」兜住，仍需红队反例测试。

## 6. 验收标准（实现期，命令 + 退出码 + 关键输出）

```bash
go test -timeout 200s ./internal/core/scheduler/... ./internal/core/market/... ./cmd/kored/...  # exit 0
make idle                 # exit 0；未开启更新任务时出站 0、CPU/fd/goroutine 达标（G-19）
make budget-check         # exit 0；开启清理后磁盘占用在 G-03 预算内
make secret-check         # exit 0；更新日志无凭据明文
make docs-check           # exit 0；ADR-0019 任务登记与 CORE/DATA-MODEL 同步
```

必测场景：关闭更新源 + 断网 → 任务短路、出站 0、无报错；开启更新源 + 篡改索引签名 → 拒绝并带 `requires_restart:true`；篡改下载资产 sha → 目标字节不变；故意装 4 个旧版本 + keep_count=2 → 自动清理后恰好保留 2 份 + 回滚可用；`--scenario` 仍按 M2 提示 `E_UNSUPPORTED`，不进静默主链。

## 7. 复审条件

1. 若要默认开启更新源、加入遥测/心跳、或把更新源地址硬编码进二进制 → 必须重开 G-10 与本 ADR。
2. 若要把 C（批量 API `items[]`）提上日程 → 需独立 ADR 明确对外 schema 与失败语义（G-24）。
3. 若 G-03 预算调整导致备份上限默认值失配 → 重新校准 `backup.max_disk_bytes` 默认常数并记入本 ADR 修订段。
4. 若出现第二个 scheduler 内置周期任务导致 ticker 不再唯一 → 重开 ADR-0019 与本 ADR（G-19）。
5. 若用户要求自动清理删除最后一份回滚材料 → 拒绝并退回提案（与本 ADR §3.5 保底规则冲突）。
