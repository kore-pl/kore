# ADR-0014: v1 范围与深度分级——广度为纲、深度分级、平台分阶段

## 背景

用户要求 v1 至少对标宝塔/1Panel 专业版。红队做了 scope 验尸：纯产品插件 288–488 人日，v1 总盘 432–650 人日，是 ROADMAP 原估（224–302）的 **2.1 倍**。于是摆在面前的不是"要不要全做"，而是三种都不体面的选项：20 个插件同级做穿 → v1 无限推迟；砍到 10 个 → 违背用户对广度的要求，也丢掉"对标"印象；维持原估 → 等于假装 2.1 倍不存在。

真问题不是工作量，是**"对标"这句话到底承诺什么**。承诺"同样能力域都在"，不等于"每项都做到专业版深度"；而如果不在文档里写清等级，用户会把基础级当生产级用——那才是真正的风险。

## 决策

1. **保留 20 插件，分两级深度**：**12 个生产级**（边界用例 + 故障注入 + 完整错误处理）/ **8 个基础级**（核心路径可用，边界用例延 v1.1）；等级落在字段上——插件 `info.json` 必须声明 `depth_level: production|basic`，商店与对标矩阵同步展示；`basic` 不得被任何预设标为"开箱可用"。
2. **v1.0 = Linux GA**；macOS / Windows 为 **preview**（编译通过 + 基础链路可跑，不承诺全功能）；三平台 GA 推到 v1.1。
3. **对外口径统一**：「覆盖 22 项能力域：12 生产级 / 8 基础级 / 6 明确不做」——README、商店首屏、安装器三处一致；**不再使用"完全对标专业版"表述**。
4. **6 项明确不做**：多用户 RBAC、集群/多机、模板市场、厂商云存储深度集成、拖拽建站、多语言。

## 备选方案对比

| 方案 | 优点 | 代价 | 为何不选 |
| --- | --- | --- | --- |
| 20 插件同级做穿 | 广度与深度都满足，宣传口径最省事 | 650 人日，v1 无限推迟；期间无法验证任何东西 | 交付无限期 = 风险无限期 |
| 砍到 10 插件 | 可在可控工期内交付 | 违背用户对广度的要求，且丢失对标印象 | 需求方向被改，不是工程权衡 |
| 20 插件分深度 + Linux GA（选） | 广度与诚实兼得；v1.0 有明确可交付边界 | 基础级质量参差，需清晰标识与升级路线 | 选它：把"深度"变成可声明的等级，而不是隐含承诺 |
| 先做面板壳不做插件 | 最快出可看的东西 | "不能建站的面板"没有使用价值 | 空壳不解决任何用户问题 |

## 后果

**正面**：广度满足（20 个能力域都在），v1.0 有可交付边界（12 生产级过故障注入、8 基础级核心路径可用），对外口径可被验证（三处文案一致 + `grep "完全对标"` 零命中），6 项不做把"以后会不会加"的争论提前关掉。

**负面**：8 个基础级插件质量参差，用户可能踩坑；需要清晰的等级标识（商店徽标 + 安装器提示）与升级路线，否则"基础级"会被读成"次品"；macOS/Windows preview 会增加支持成本，用户会拿着 preview 的问题来问 GA 的承诺。

**技术债**：v1.1 要把 8 个基础级升生产级，**升级判据必须可测**（边界用例覆盖率、故障注入通过项、错误码完整性），否则"升级"变成拍脑袋；对标矩阵每行要维护状态字段（生产/基础/不做），文档与商店同步成本上升。

## 验证方式

```bash
# v1.0 gate：20 个插件仓库可装可卸
for p in ../kore-plugin-*; do kored plugin install "$p/dist/"*.tar.gz && kored plugin remove "$(basename $p)"; done
# 12 个生产级过故障注入（kill -9 / 内存超限 / socket 拒绝 / 畸形帧）
make fault-inject PROD=12                    # 期望 12/12 通过
# Linux 全矩阵 smoke
make compat-info && make check               # Tier A 矩阵全绿
# 对外口径三处一致，且不再出现"完全对标"
grep -rn "完全对标" README.md docs/ web/ cmd/ && echo "FAIL: 仍有旧口径" || echo "OK"
grep -c "12 生产级" README.md docs/FEATURE-PARITY.md docs/SCENARIOS.md
# 对标矩阵每行有状态
awk -F'|' 'NF>3 && $4 !~ /生产级|基础级|不做/ {print "缺状态: "$0}' docs/FEATURE-PARITY.md
```

## 复审条件

基础级插件在真实使用中产生安全事故（如 waf 误判放行、防火墙规则误删）→ 立即降级为"实验性"或暂停收录，不等 v1.1；v1.1 升级进度落后 > 2 个迭代 → 重新评估是否砍掉 4 个卫星插件（优先保留站点/域名/SSL/备份四类高频）；macOS/Windows preview 的支持成本超过 Linux GA 的维护成本 → 考虑把 preview 明确标为"社区支持"或暂时下线。
