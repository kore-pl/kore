# ADR-0012: 场景预设 + 软件商店——embed 快照、离线可装、零后台出站

## 背景

v1 对标宝塔/1Panel 专业版，用户期望"装完就能用"而不是"装完先去商店点 20 个插件"。若让用户从零逐个安装，第一次上手成本等于自己搭环境，违背"效率优先、最短路径"的体验锚点。但内核的定位是只定规则：把插件清单硬编码进 `internal/core` 会直接违反薄壳红线，也让预设无法独立于内核版本演进。

于是需要把"装什么"从内核里拿出来，同时保证**离线/内网环境也能一次装完**——这是宝塔类产品在国内内网场景的真实门槛。

## 决策

1. **预设定义在索引仓库**：`kore-plugins/presets/*.json`，可独立更新，不随内核发版；kore 构建时把预设**embed 快照**进二进制，首次安装离线可用。
2. **安装入口**：`kored install` 交互式选场景；非交互 `--scenario <id> --yes`；`--offline-dir` 指定本地包目录，支持完全无网安装。
3. **商店 = 索引仓库 + kore 端 `store` 模块**：分类、搜索、依赖提示、capabilities 展示；**无账号、无评分、无人工审核**，索引只是发现渠道。
4. **联网边界**：运行期**零后台出站**；只有用户显式触发 `POST /api/v1/store/refresh` 与安装/更新下载才出站；支持本地目录（`file://`）与自建镜像源（`store.mirror`）。
5. **安装为异步任务**：提交后返回 job id，前端轮询 `GET /api/v1/store/jobs/{id}`；失败按预设整体回滚或部分成功，语义由 [SCENARIOS](../SCENARIOS.md) 定义。

## 备选方案对比

| 方案 | 优点 | 代价 | 为何不选 |
| --- | --- | --- | --- |
| 内核内置插件清单 | 实现最简单，零网络依赖 | 违反"内核不绑架功能"；加插件要发内核版本 | 与薄壳红线③直接冲突 |
| 首次安装强制联网拉清单 | 清单永远最新，内核最干净 | 离线/内网环境直接不可用；首次安装多一个失败点 | 内网主力场景直接出局 |
| 预设 embed + 可刷新 + 离线目录（选） | 离线可装；预设可独立演进；内核零硬编码 | embed 快照会滞后，需 `--preset-refresh` 才取最新 | 选它：把"联网"降为可选项而非前提 |
| 所有插件打进单二进制 | 一次分发，无安装步骤 | 体积爆炸，直接破 25 MiB 预算 | 与资源预算门禁冲突 |

## 后果

**正面**：断网机房可一次装完；预设由索引仓库独立迭代，内核不必为新增场景发版；`internal/core` 不含任何插件清单，红线③不被侵蚀；商店刷新与安装下载是仅有的两个出站点，审计面小。

**负面**：embed 快照天然滞后于索引最新预设，用户需 `--preset-refresh` 才能拿到新预设；预设与插件版本区间耦合，需兼容校验（`requires_kore` + 版本区间），否则"预设装了不兼容的组合"。

**技术债**：预设 JSON schema 要版本化（`schema_version`），否则字段演进会破坏老快照；镜像源与缓存失效策略要写清（`etag`/`last-modified` + 显式 refresh）；异步任务的 job 状态清理与失败回滚路径要测；`--offline-dir` 的包校验必须与在线链路完全同源，不能两套逻辑。

## 验证方式

```bash
# 断网环境按场景安装（先拔网/关防火墙出站）
kored install --scenario web-lite --offline-dir ./pkgs --yes
# 预设快照可刷新且版本可见
kored install --preset-refresh && kored doctor | grep preset_snapshot_version
# 运行期零后台出站：空载 ss 应无 kored 出站连接
ss -tnp | grep kored || echo "空载零出站"
# 商店刷新是唯一出站入口
curl -s -X POST 127.0.0.1:8787/api/v1/store/refresh
# 异步安装任务可轮询
curl -s 127.0.0.1:8787/api/v1/store/jobs/<job_id>
```

## 复审条件

预设数量 > 12 且相互差异 < 30% → 合并为更少的"能力包"，否则用户面对的选择成本反超手装；用户频繁自定义预设 → 考虑 preset 可导出/导入（但仍不入内核）；若 embed 快照滞后导致实际安装事故（预设引用了已下架插件）→ 评估首次安装强制 refresh 或预设内联兜底版本。
